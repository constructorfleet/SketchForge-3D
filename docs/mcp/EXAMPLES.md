# MCP examples

## Build and export a local project

This executable workflow uses the local project store. It creates a temporary project, adds an 80 × 56 × 3 mm mounting plate, reads the resulting scene, exports an `.skf` file, and removes the temporary directory when it exits. It does not need a browser, running editor, or API token.

For the `.skf` file's archive layout, validation, and compatibility behavior, see the [project format guide](../SKF_PROJECT_FORMAT.md) and [generated format reference](../SKF_FORMAT_REFERENCE.md). REST-based automation is covered separately in the [REST API guide](../REST_API.md).

From the repository root, run the checked command below. It builds the engine and then runs the isolated workflow:

```sh
!!!include(./examples/run-local-project.sh)!!!
```

The [example source](./examples/local-project.mjs) starts the repository MCP server, reads the current `tools/list` registry, validates each tool argument against its advertised input schema, and then invokes those tools over JSON-RPC. The [MCP tool reference](./TOOLS_REFERENCE.md) lists the complete current registry and schemas. The executable contract is checked by [`tests/docs/mcp-examples.test.mjs`](../../tests/docs/mcp-examples.test.mjs).

This example operates on a temporary local project directory and deletes it in a `finally` block. To target a live editor or a persistent local project, follow the setup and targeting guidance in the [SketchForge MCP skill](../skills/sketchforge-mcp-skill/SKILL.md).

## Drive a shape from parameters

Six tools manage a project's named parameters and bind shape fields and sketch dimensions to them, and six more manage [configurations](#configurations). They work in local mode, against a server when a tool call passes `url` (through REST v1 [parameters and expressions](../REST_API.md#parameters-and-expressions) and [sketch constraint bindings](../REST_API.md#binding-sketch-constraints), which need `SKETCHFORGE_API_TOKEN`), and on a server's `/mcp` endpoint.

| Tool | Does |
| --- | --- |
| `sketchforge_list_parameters` | Returns the table, with each resolved `value`, and `bindingIssues` for bindings that no longer resolve. |
| `sketchforge_set_parameter` | Creates a parameter when given `expression` and `dimension`. If the name exists, it overwrites that parameter instead of refusing. Either field alone changes an existing parameter. The reply has `created`. |
| `sketchforge_rename_parameter` | Renames a parameter and rewrites every expression and shape binding that uses it. |
| `sketchforge_delete_parameter` | Deletes a parameter that nothing uses. |
| `sketchforge_set_shape_expression` | Binds one shape field to an expression, or clears the binding with `expression: null`, which keeps the current number. Repeating the stored expression changes nothing and writes nothing. |
| `sketchforge_bind_sketch_constraint` | Binds one distance, radius, diameter or angle constraint of a shape's sketch to an expression, re-solves the sketch and rebuilds the shape. `expression: null` unbinds it and keeps its value. The reply has the shape and the constraint as `{ id, kind, value, expression }`. |

A write to a parameter returns the whole table and the shapes it rebuilt, so the new geometry is in the reply. For example, these calls make a box whose width and position follow `wall`:

```json
{ "name": "sketchforge_set_parameter", "arguments": { "projectId": "bracket", "name": "wall", "expression": "2", "dimension": "length" } }
{ "name": "sketchforge_set_shape_expression", "arguments": { "projectId": "bracket", "shapeId": "<box id>", "field": "width", "expression": "wall * 5" } }
{ "name": "sketchforge_set_parameter", "arguments": { "projectId": "bracket", "name": "wall", "expression": "3" } }
```

The last call answers `created: false` and lists the box with `width: 15`. A bare number takes the parameter's unit, so `3` in a length parameter is 3 mm. Shapes in replies have the same fields as `GET /api/v1/shapes`.

With `url`, these tools write the server's stored project through REST, while `sketchforge_create_shape`, `sketchforge_update_object` and the other editor tools act on an open editor tab through its bridge. The parameter tools therefore bind the shapes stored under `projectId`, and an open editor tab, which keeps its own copy, need not show the change.

### Configurations

A configuration is a named set of parameter overrides, such as a `large` variant where `wall` is `3`. Six tools manage them: `sketchforge_list_parameter_configurations`, `sketchforge_create_parameter_configuration`, `sketchforge_rename_parameter_configuration`, `sketchforge_set_configuration_override`, `sketchforge_delete_parameter_configuration` and `sketchforge_activate_parameter_configuration`. They call `/api/v1/parameter-configurations` in remote mode.

```json
{ "name": "sketchforge_create_parameter_configuration", "arguments": { "projectId": "bracket", "name": "large", "overrides": { "wall": "3" } } }
{ "name": "sketchforge_activate_parameter_configuration", "arguments": { "projectId": "bracket", "name": "large" } }
{ "name": "sketchforge_activate_parameter_configuration", "arguments": { "projectId": "bracket", "name": null } }
```

Creating a configuration does not activate it. Activating one, or changing an override of the active one, rebuilds every bound shape in the same write and lists the rebuilt shapes in `shapes`; `name: null` returns to the base table. Every write replies with `configurations`, `activeConfiguration` and the table as the active configuration resolves it. A refused activation, for example one whose override would make a bound width negative (`invalid_expression` with `reason: "outOfRange"`), leaves the project, the active configuration and the geometry as they were. Deleting the active configuration returns the project to the base table and rebuilds bound shapes, so it can be refused with the same codes as an activation (`invalid_expression`, `shape_locked`, `geometry_failed`), leaving it in place. A configuration `name` must be a string; a number is refused as `invalid_request` rather than read as text. Unknown and duplicate names answer `configuration_not_found` and `configuration_exists`.

### Refusals

A refusal is an MCP tool error. Its first line ends with the REST error code in brackets; a second line, when present, holds the detail as JSON. Local mode builds both from the engine's REST error mapping and request checks, so it answers exactly as remote mode does:

```text
Parameter "wall" is used by lip, shape <box id>. [parameter_in_use]
{"parameter":"wall","reason":"parameterInUse","dependents":["lip"],"shapeDependents":[{"shapeId":"<box id>","fields":["width"]}],"sketchConstraintDependents":[],"configurationDependents":[]}
```

| Code | When | Detail |
| --- | --- | --- |
| `invalid_expression` | Bad syntax, an unknown name, the wrong dimension, a cycle, or a bound result out of the field's range. | `expressionError` with `code`, `message`, `span` and `cycle`; `shapeId` and `field` for a binding; `value`, `min`, `max` for a range. |
| `parameter_not_found` | Changing, renaming or deleting a name that does not exist. A set without `dimension` says to send both fields to create. | `parameter` |
| `parameter_exists` | Renaming to a name already in use. | `parameter` |
| `parameter_in_use` | Deleting a parameter that something references. | `dependents`, `shapeDependents`, `sketchConstraintDependents` (`shapeId`, `constraintIds`), `configurationDependents` (configuration names) |
| `shape_locked` | A binding, or a parameter change that would rebuild it, touches a locked shape. | `shapeId`, `fields`; for a sketch constraint, `shapeId` is the locked shape or the locked group holding it |
| `geometry_failed` | A parameter change leaves a bound sketch unsolvable. | `shapeId`, `constraintIds` |
| `unapplicable_fields` | The shape cannot bind that field. | `fields` |
| `invalid_request` | A bad name or dimension, an empty expression or one over 10,000 characters (the sentence says so), or a set with neither field. | `parameter`, `reason` when the engine refused it |
| `invalid_project_id`, `invalid_shape_id` | `projectId` or `shapeId` is missing, blank or malformed. | |
| `limit_exceeded` | The table is full. | |
| `configuration_not_found`, `configuration_exists` | A configuration name that does not exist, or one already taken. | `configuration`, and `reason` (`unknownConfiguration`, `duplicateConfigurationName`); `parameter` only when the refusal is about one parameter's override |
| `shape_not_found`, `project_not_found` | The id is not in the project or store. | |

A sketch-constraint binding answers with the same codes, naming `constraintId`: `invalid_expression` (including `reason: "outOfRange"`), `unapplicable_fields` for a constraint that cannot bind, or `reason: "conflictingBinding"` when a bound size of the same shape, or of a group that holds it, drives that dimension (and the reverse, from `sketchforge_set_shape_expression`), `invalid_request` for a missing or unknown `constraintId`, and `geometry_failed` with `constraintIds` when the sketch cannot be solved.
