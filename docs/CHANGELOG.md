# Changelog

## Unreleased

- Fixed server-side CAD turning a shape the wrong way, so a fillet, chamfer or STEP export of a shape that had been rotated came back facing somewhere else. The editor orients a shape with `THREE.Euler(rotationX, rotation, rotationZ)` in its default `XYZ` order -- the matrix `Rx * Ry * Rz` -- while the exact-solid builder negated the yaw and applied the three rotations in the opposite order. Of seven representative rotations, four disagreed with the editor: yaw alone came out mirrored, and every combination of two or more came out in the wrong order. Only single-axis pitch and roll were right.

  Nothing caught it because the shapes people fillet while turned are usually symmetric: a box, a cylinder or a sphere is unchanged by the 180-degree error a negated yaw produces, so the bug was invisible until an asymmetric shape -- a wedge, a roof, a cone with a top radius, a pyramid -- was rotated and then treated. There is now a test that measures the solid's centre of mass, which is the part a wrong orientation moves, against the editor's own matrix for all four of those kinds; a bounding box cannot see this, since mirroring a solid does not change its extents.

- Fixed the desktop installers never being attached to a release, which is why 1.2.0 and 1.2.1 both have none even though every build succeeded. The attach job still assumed it owned the release, as it did before releases were driven from `main`: it refused to continue when the release already existed and was not a draft, and a later step asserted the release *was* a draft. release-please now creates the release when its pull request merges, and creates it published -- because GitHub does not make the git tag for a draft -- so both checks rejected every release there will ever be. The job now attaches to whichever release the tag has, draft or published, and only creates one when nothing is there.

- A dispatched desktop release now builds the released tag rather than whatever `main` says at the time, falling back to the checked-out commit when the tag does not exist yet. Re-running an old version used to package current `main` and label it with that version, which is precisely what recovering a missed release asks for. The tag check alongside it no longer fails when the tag points somewhere other than the dispatch commit, since that is now deliberate.

- The MCP bridge is now a published binary, so an AI client can start it with `npx -y -p @constructorfleet/sketchforge3d sketchforge-mcp` instead of needing a clone of this repository and a built client. It moved from `scripts/` into the client package as `mcp/server.mjs`, which is also where its two macro tools can find the runner they spawn -- previously they located it by walking up to the repository root, which does not exist in an install. A Python macro now relies on `sketchforge3d` being installed from PyPI, since only a checkout carries the Python source. `npm run mcp:sketchforge` still runs the same file from a checkout, and the version the bridge reports is the package's rather than a hand-written `0.1.0`. The Claude Desktop and Codex example configs use the npx form.

- The REST API now reads back everything it can be told, which it had been promising and not doing. A shape summary carried only placement, size, rotation, the three flags, `sides` and `text`; every other parameter a kind is built from -- a tube's wall thickness, a cone's radii, a gear's teeth, a loft's profiles, text's font, the taper fields -- was dropped on the way out, so reading a shape, changing one number and sending it back lost all of them. Threads and revolves fared worse: they are stored as a mesh carrying a sketch profile and revolve settings, and the summary showed none of that, so a client could not read a thread's pitch, could not change the pitch of a thread it had just created, and could not tell a thread from an imported STL. The summary is now driven by the same table that builds a shape from a request, so a parameter the API can set is a parameter it reports, and a revolve also reports its sweep under `revolve` and the outline it ran round under `profile`.

- `kind` still reports what the project stores -- a `cube` is a box whose sides match, and a revolve is a mesh -- because that is what the editor shows and what every existing caller already reads. The missing half is a new `requestKind`: the kind a `POST` would need to build the shape again, which is `box` for a cube and `revolve` for a thread, and which is absent for a shape no request reproduces, such as a boolean cut or an imported mesh. That absence is what distinguishes a thread from an STL, which by stored kind alone was impossible.

- `PATCH /shapes` now applies the fields it reports, or refuses them by name. It had applied only name, colour, placement, size, rotation and the flags; anything else -- `sides`, `bevel`, a thread's `pitch` -- was accepted, answered `200`, and changed nothing, which is the one answer a script cannot tell from success. A parameter belonging to another kind, a sweep setting on a shape with no sweep, and a field this version has never heard of are now all refused with `422` and a `fields` list naming them, and the request is refused whole so a typo cannot half-move a shape. Changing a revolve's pitch, turns or outline rebuilds its mesh on the server with the same manifold build `POST` uses, keeping the shape's id, placement and any scale it had been resized to.

- Every error now carries a machine-readable `code` beside its sentence. The status alone was ambiguous in both directions that matter: `404` meant a missing project, a missing shape or an API with no token set, and `409` meant both a busy project worth retrying and a locked shape that never will be. Both client libraries had been matching on the prose to tell them apart, which made every wording change a breaking one. They now read the code and keep the prose match as a fallback for an older server.

- Fixed `POST /shapes` writing a project that could not be read back when asked for a gear. The project format requires a gear to carry its tooth count, tooth size and type, and to keep the count between 6 and 64; the API left all three unset when a request did not name them and clamped the count at 3, so `{"kind": "gear"}` produced a package whose next read threw. Gear parameters are now clamped by the editor's own normalizers, which are exactly what the format accepts, and all three are always written. A cone's base radius is written out for the same reason -- so a cone read back says what it is standing on rather than relying on a half-the-width fallback.

- Fixed the TypeScript client typing a loft's profile shapes as `square | circle | triangle | hexagon`, none of which the server accepts: all four fell through to the default, so a loft asked for in good faith came out the wrong shape with no error anywhere. They are `Oval`, `Rectangle`, `Triangle`, `Pentagon` and `Hexagon`. Both clients also gained the new summary fields and a round-trip helper -- `shapePatchFromSummary` and `ShapeSummary.as_patch` -- which turn a shape that was read into the change that would reproduce it.

- Documented that `NPM_TOKEN` must be a granular or automation token. The 1.2.0 npm publish failed with `EOTP` -- npm asking for a one-time password, which a workflow cannot supply -- because a classic publish token is still subject to two-factor authentication on writes. This is an account-side fix, not a repository one, so it is written down in `docs/PUBLISHING_CLIENTS.md` next to the rest of the npm setup.

- Fixed the macOS desktop builds failing on every signed release, which is why 1.2.0 has no installers attached. The step that writes the notarization key ran a `node <<'NODE'` heredoc indented inside the workflow YAML; a quoted heredoc needs its terminator at column 0 of the script, YAML strips only the block scalar's own indentation, so bash never found the terminator and the step died with "syntax error: unexpected end of file". The script now lives in `.github/actions/build-mac/write-notary-key.mjs`, where indentation cannot break it, and its PEM-or-base64 decoding has unit tests. The failure only appeared once the signing secrets were configured, because the unsigned path never reaches that branch.

- Fixed the PyPI publish failing on every release with "Invalid attestations supplied during upload". `release.yml` was a reusable workflow called by `release-please.yml`, and PyPI's trusted publishing verifies the OIDC claim of the top-level workflow -- so the upload arrived identifying itself as `release-please.yml` and did not match the registered publisher. PyPI does not support reusable workflows for trusted publishing at all. Both publishing workflows are now dispatched by release-please rather than called, which is what the desktop release already did, and `release.yml` no longer has a `workflow_call` trigger so this cannot be reintroduced by accident.

- `latest` on the Docker image now means the latest release. Two workflows were publishing the image and both moved `latest`: the release, and every push to `main`. Pushes to `main` are still built and published, as the `main` tag and by short SHA, but no longer move `latest`.

- Pull request titles are now checked against the conventional commit format, and the check fails if they do not match. This is not tidiness: the repository squash-merges with the title as the commit subject, and release-please reads those subjects to decide the next version, so a title it cannot parse means the change silently does not count towards a release. The allowed types are read from release-please's own configuration so the two cannot drift. Commit subjects inside a pull request are reported as warnings rather than failures, since they only reach `main` when a pull request is merged with a merge commit rather than squashed.

- Fixed a release producing no artifacts. The release was created as a draft, and GitHub does not create the git tag for a draft -- the tag appears only when the release is published -- so there was nothing for the publishing workflows to trigger on. The tag was also named `sketchforge-v1.1.0` rather than `v1.1.0`, because release-please includes the component in the tag when a package name is configured. Both are corrected, and the publishing is now driven directly from the release workflow rather than from the tag, because a tag pushed by a workflow using the default token cannot start another workflow run at all.

- Releases are now driven from `main` by release-please rather than by a hand-typed tag. Every merge updates a standing release pull request carrying the next version and its notes, and bumping all three manifests -- the app and both client libraries, which now share the app's version. Merging that pull request tags the commit and drafts the GitHub release; the tag then publishes the Docker image (tagged with the version, not just `latest` from `main` as before) and both clients, and builds the desktop installers as it already did. Previously the draft release was created by the *desktop* workflow, so a release existed only as a side effect of packaging an Electron app and a code-signing failure on one platform meant no release at all. The hand-written changelog is left alone: release-please generates the notes on the release itself, where a list of commit subjects is the right level of detail.
- Added client libraries for the REST API, in TypeScript (`@constructorfleet/sketchforge3d`) and Python (`sketchforge3d`), so a script or an LLM can drive SketchForge by writing *macros*: short parameterised scripts that build a part. Both wrap projects, shapes, edges and server-side fillets and chamfers with the server's own field names, and both come with a macro runner (`npx sketchforge-macro file.mjs --holes=7`, `python -m sketchforge3d.macro file.py --holes=7`) that connects from the environment and hands the macro a project to build in. A macro declares what should happen on its second run -- a fresh project each time, or one project emptied first, or one left as it is -- because a build script that quietly appends to what it finds doubles the part on every run. Three worked examples ship with each library and double as its integration tests: a plate with a computed row of tapped holes, a bolt circle of N holes on a ring of radius R, and a parametric box filleted on the server. The MCP bridge gained `sketchforge_list_macros` and `sketchforge_run_macro`, which run a macro from the directory named by `SKETCHFORGE_MACRO_DIR` and nothing else -- there is deliberately no way to send code to be executed. See `packages/sketchforge-client/README.md` and `packages/sketchforge-py/README.md`.
- The REST API can now combine shapes, which is what upstream issue #55 was actually asking for: `POST /booleans` subtracts one or more shapes from another, `POST /groups` and `DELETE /groups` group and ungroup, and `POST /parts` splits a shape into the separate bodies a cut left behind. A script could already make a plate and a row of holes but not take one out of the other, so a parameterised bracket stopped one step short of being a bracket. Grouping is how this app subtracts, so the two write endpoints are one operation with two front doors -- name the solids and the holes explicitly, or group a selection and let each shape's own hole flag decide. The result is the same group record the editor makes, so a project cut this way opens there as an ordinary group and ungroups back to the shapes it was made from.
- A boolean cut on the server is an exact OCCT operation rather than a mesh CSG, which has two consequences worth knowing. The editor grows every cutter by 0.05mm first, because a mesh CSG resolves two coplanar faces unpredictably; the server does not need to, so a flush-bottomed pocket comes out at the depth that was asked for. And the cut result keeps its exact geometry alongside the mesh, so a fillet or a STEP export of a cut part reads true surfaces. A cut that would remove the whole solid is refused with the project untouched, rather than the shapes quietly disappearing.
- Fixed the server building a box from one corner outwards while building every other kind around its middle. Nothing showed it until now, because a fillet's result is recentred before it is stored -- but it meant a hole placed against a box landed half a box away, which made every boolean cut on a box wrong by half its width.
- Updated dependencies to clear every critical and high security advisory: Next (the one critical), js-yaml, fflate, Electron, and Vitest move within their existing ranges, and nanoid, postcss, sharp, source-map-js, undici, brace-expansion, fast-uri, http-cache-semantics, and @xmldom/xmldom are pinned forward with `overrides` because the packages that depend on them have not released a fix yet. The CAD stack -- occt-wasm, brepjs, three -- is deliberately untouched, so geometry behaviour is unchanged. Eight moderate advisories remain in the electron-builder packaging toolchain, which only a major version bump resolves.
- Cleared the last eight moderate advisories, all of which sat in the electron-builder packaging toolchain, by pinning `global-agent` forward with an override. npm reported the only remedy as a major bump to `electron-builder@26`, but the project is already on 26, and npm's own suggested fix resolved to 26.5.0 -- ten minor versions backwards, which would have traded the advisories for the packaging fixes since. The single real advisory is a denial of service in `sprintf-js` reachable only as a format string, and `sprintf-js` has no patched release and no prospect of one: 1.1.3 is both the latest version and the whole vulnerable range. Everything else in the chain was flagged merely for depending on it. So the fix had to cut the chain rather than follow it, and `global-agent` is the place it is thinnest: v4 dropped `roarr`, which is what pulled `sprintf-js` in, and the only thing `@electron/get` asks of it is `bootstrap()`, which v4 still exports with the same `GLOBAL_AGENT_*` environment contract. Overriding `@electron/get` itself to v5 would also have worked and was the more obvious move, but v5 is ESM-only, outside the `^3.0.0` that `app-builder-lib` declares, and swaps the `got` downloader for `fetch`, which silently discards the request timeout, the proxy agent, and the server-error retry classification that electron-builder passes it -- three regressions in the Electron download path in exchange for the same clean audit. This whole chain is a devDependency used only to build installers, so none of it ever shipped in the app.
- Updated dependencies to clear every critical and high security advisory: Next (the one critical), js-yaml, fflate, Electron, and Vitest move within their existing ranges, and nanoid, postcss, sharp, source-map-js, undici, brace-expansion, fast-uri, http-cache-semantics, and @xmldom/xmldom are pinned forward with `overrides` because the packages that depend on them have not released a fix yet. The CAD stack -- occt-wasm, brepjs, three -- is deliberately untouched, so geometry behaviour is unchanged.
- Fixed the static export build, which failed outright: the app-update route declared `dynamic = "force-dynamic"`, which `output: export` refuses rather than skipping. The declaration was redundant -- every handler there reads request headers, so the route is dynamic in a server build regardless.
- Fixed `npm run export` not setting `STATIC_EXPORT` on macOS or Linux. It used `set VAR=value&&`, which is cmd.exe syntax, so off Windows it quietly built a server bundle while reporting success -- including in the Cloudflare deploy workflow, which is why the broken export build went unnoticed. The static export build now also runs in CI.
- Fixed clicking a project doing nothing but emptying the dashboard when server-side storage was on. Opening a project checks it still exists first, in case another tab deleted it, and that check read the browser's own list -- which server storage deliberately leaves empty, so every project looked deleted and every click bounced back to a dashboard it had just cleared. The check now asks whichever store owns the list.
- Repeat is also on the MCP bridge as `sketchforge_pattern_objects`, so a script can ask for a bolt circle rather than working out eight positions.
- Added Repeat to Arrange: a selection can be copied into a row, spaced along X and Z, or around a ring about a centre point. A full turn divides evenly so the last copy does not land on the first, while a partial sweep puts one copy at each end -- "three across 90 degrees" means 0, 45 and 90. Copies around a ring turn to follow it by default, which is what a spoke or a vane wants and a bolt hole does not mind, and the whole pattern lands selected as one undo step however many copies it made.
- Added a thread catalog to the shapes menu: pick a standard size -- metric coarse M2 to M20, or imperial UNC #4-40 to 1/2-13 -- and it drops a complete threaded rod, or the tapped hole for that size cut 0.2mm wider so the bolt fits. Each comes with its core fused in, since a bolt is the thread standing on its shank and a tapped hole is the thread plus the hole it cuts; a Core radius row in the object panel sets it to 0 for the bare helix, which is what a spring wants. The size carries its own pitch, which is the part nobody should have to look up, and the dropped shape stays a revolve, so its pitch, turns and sweep remain editable in the object panel. The same sizes are available over the REST API and MCP as `size: "M8"`, with `length` instead of turns and `hole: true` for the tapped form.
- The rotate sketch operation now takes a pitch, so a revolve can rise as it turns: a profile swept along a helix makes threads, springs, augers and worm gears, which a plain revolve cannot. Pitch is the axial rise per turn and its sign is the handedness -- negative is a left-hand thread -- with Turns setting how far the sweep goes. Pitch at zero is the plain revolve it always was. Both appear in the object panel beside Sweep, and the sketch preview follows them live.
- Threads and revolves can now be created over the REST API and the MCP bridge, which is where they are least pleasant to place by hand: `kind: "revolve"` takes a closed outline and a pitch, and `kind: "thread"` derives the ISO metric profile from a diameter and a pitch, so an M8 is one request. The result stays editable as a revolve in the editor afterwards.
- Added Distribute to Arrange, for upstream issue #51: two buttons spread three or more selected objects evenly along whichever axis they are already most spread along, either with equal gaps between them or at an equal centre-to-centre pitch. The two give the same answer for objects of one size and differ once the sizes differ, so each button says what it keeps equal and what it lets vary. The outermost two keep their places and define the span, and a locked object between them stops the operation rather than being moved. Also available to the MCP bridge as `sketchforge_distribute_objects`, where the axis and spacing can be given explicitly.
- The REST API can now create every parametric kind the editor can -- cones, spheres, half spheres, tori, tubes, rings, polygon prisms, pyramids, roofs, wedges, icosahedra and gears, alongside the boxes, cylinders, text and lofts it already took. Only meshes, sketches and scribbles are left out, since those need geometry or a drawn profile rather than numbers.
- Server-side fillet and chamfer now also build roofs, wedges, barrel roofs, pyramids, and tori exactly, leaving only the kinds whose geometry comes from a font or a tessellation (text, gears, sketches, scribbles, icosahedra) to the editor.
- The edge listing now says which edges can actually be rounded. A seam -- where one curved surface meets itself, along a cylinder's side or around a torus -- has no two faces to blend, so asking for every edge now rounds every edge that can be, naming a seam outright is an error rather than a silent skip, and a shape with no roundable edges says that instead of blaming the radius.
- Fixed one failed CAD operation breaking every later one. An OCCT call that throws leaves the kernel in a state its own API cannot repair, so a self-hosted server would answer "null function or function signature mismatch" to everything until restarted, after a single fillet radius that did not fit. The kernel is now discarded and rebuilt after a failure, as the editor's worker already does.
- Server-side fillet and chamfer now work on every parametric kind the server can build exactly, not just boxes: cylinders (round, faceted, oval, and tapered), cones, spheres, half spheres, lofts, polygon prisms, tubes and rings. Each is rebuilt as true geometry -- a round cylinder is a cylinder, so a fillet lands on a real cylindrical surface rather than on a 96-sided approximation of one. Kinds whose geometry is font- or tessellation-derived still report that they need the editor.
- Fixed a shape losing its rotation when filleted through the REST API. The geometry is now built turned the way the shape sits, so a treated shape keeps its angle instead of springing back to square.
- The REST API can now round and cut edges on the server: `GET .../shapes/{id}/edges` lists a shape's edges and `POST .../shapes/{id}/treatments` applies a fillet or chamfer. The editor does this in a browser worker, so every client downloads the 22 MB CAD kernel and runs the solid modelling itself; a self-hosted server can now do that work instead. A box is rebuilt from its dimensions so its fillet is exact rather than a rounding of a tessellation, and the result stores exact geometry so STEP export and later treatments build on true surfaces. A radius that does not fit the shape is reported rather than approximated.
- Added a REST API for scripting projects, enabled with `SKETCHFORGE_API_TOKEN` alongside server-side storage. It creates projects and adds, changes, and deletes shapes described as JSON, with no editor open, so an LLM or a build script can generate a parameterised design instead of placing each shape by hand. Shapes it cannot build from parameters alone are reported as unsupported rather than substituted. See `docs/REST_API.md`.
- Added server-side project storage: setting `SKETCHFORGE_PROJECTS_DIR` makes the server hold every project instead of the browser, so a cleared browser profile no longer takes them with it. The dashboard reads its list from the server and autosaves there, projects already in a browser are moved up on first run, and a browser whose projects cannot all be moved keeps its own storage rather than showing half a list.
- Numbers can now be typed during a drag, the way FreeCAD and Tinkercad allow. While dragging a rotate, lift, or height handle, typing digits sets the exact value shown on the live dimension label instead of the dragged one; Backspace corrects a digit and Escape returns to following the pointer. Typed digits no longer reach the camera-view shortcuts.
- The Placement section of the object panel now starts expanded, since its numeric position and rotation fields are the only way to enter an exact angle and were easy to miss collapsed.
- Added a Placement section to the object panel with numeric X, Y, Z position and rotation fields. The panel could already set an exact size but not an exact place or angle, so precise work meant nudging with the arrow keys. Negative and fractional values are accepted, and rotation reads as a signed turn so a shape stored at 350 degrees shows as -10.
- Fixed the dashboard hanging with "Maximum update depth exceeded" when a project had a tilted workplane. Normalising such a workplane alternated between two values in the last digits rather than settling, so the effect that persists the project list never saw a stable result and re-ran until React gave up. A workplane that is already a valid frame is now left alone, and that effect can no longer rewrite the same list twice.
- Added a scene list: a panel showing every shape, with search by name or kind, expandable groups, per-shape show/hide, lock and delete, and group/ungroup for the selection. It shares the right-hand rail with Object details, so collapsing one gives its room to the other.
- The snap grid moved to the foot of the right-hand rail. It used to be two controls — one docked inside Object details, one floating when nothing was selected — so it moved around or vanished depending on what was selected.
- Renamed the left rail from "camera controls" to "view tools", in markup and in what screen readers announce. It holds the workplane tool, the ruler, and now the scene list, so naming the whole group after the camera was wrong.
- The view cube can now be dragged to orbit the camera, the way Tinkercad's does, and shows a grab cursor to say so. Clicking a face still snaps to that view; a drag that turned the camera no longer also snaps on release.
- A STEP export where every shape was skipped now names the shapes and why, instead of reporting "No box/cylinder/sphere or imported STEP solids to export" — which contradicted what was on screen when the skipped shape was a sphere.
- STEP export now honours a cylinder's facet count and a shape's taper. A deliberately faceted cylinder exports as the prism it is instead of a round cylinder, and keeps its rotation; a tapered box or cylinder exports with its taper instead of straight-sided. A taper that cannot be built exactly is reported as skipped rather than written as a different shape.
- STEP export now includes shapes carrying a fillet or chamfer, whose exact geometry lives in `cadBrep`. They were skipped as having no B-Rep source, and an export containing nothing else failed outright.
- Added a projection toggle to the camera controls, switching between perspective and orthographic view. The capability already existed on the `O` key but had no visible control; the button shows which projection is active and keeps in step with the shortcut.
- The snap grid now applies globally rather than relative to where a shape started. Resizing a 1mm-tall box with the grid at 5mm lands on 5mm instead of 6mm, and the lift handle moves a selection onto the grid rather than by whole steps from wherever it sat. Width and depth already behaved this way; height and elevation were the outliers.
- The test suite is now type-checked (`npm run typecheck:tests`, wired into `npm run ci` and GitHub CI). It previously was not, so a change to a function's signature could leave its tests calling it with the old arguments and fail only at runtime.
- Fixed a tapered shape losing its taper when grouped with a hole. The fast boolean paths substituted a plain cuboid or primitive solid built from width, depth, and height, which cannot express a taper; they now decline a tapered shape and fall back to its real mesh.
- Fixed holes whose profile carries its own absolute dimensions — a loft's independent top end, and the taper rows on every other kind — being padded only at their generic size before subtraction. The cutter changed shape instead of growing, so the hole came out wrong and its unpadded end stayed coplanar with the solid, tearing faces off the result.
- Fixed the rotation axis rings never appearing: they were parented to the selection-helper group, which is rebuilt whenever the selection changes and hidden for the duration of a rotate drag.
- Added interface localization in English, Czech, German, Spanish, French, Polish, Brazilian Portuguese and Russian. The language follows the system by default and can be changed in Settings → Language; the desktop tray and update dialogs follow the same choice. Local server errors and editor notices are translated as well; MCP tool results stay in English. Languages are ICU JSON catalogs (see `docs/TRANSLATIONS.md`); the non-English translations were made with AI help and have not been reviewed by native speakers yet.
- Added a Loft primitive that morphs a solid between two 2D cross-sections. Each end is an Oval, Rectangle, Triangle, Pentagon, or Hexagon with independent size and rotation, the way cone's Top Radius works independently of its base. Wired into `.skf` projects and the MCP bridge's `sketchforge_create_shape` as `kind: "loft"`.
- Replaced the corner rotate-handle icons with three world-space coloured axis rings as the primary rotation control on desktop. Near edge-on rings tip up slightly so they stay hittable, and opacity eases for hover, active drag, and camera motion. The corner icons remain as a fallback on touch and narrow viewports, a "Use classic rotate handles" setting forces them everywhere, and `?rotationMode=classic|rings` overrides both.
- Added a Center view on selection button next to Home, bound to Shift+F. It keeps the current viewing direction, moves the orbit target to the middle of the selection, and backs off far enough for the selection to fit, changing distance for a perspective camera and zoom for an orthographic one.
- Added a Center on workplane button to Arrange, which places the selection in the middle of the build plate. The selection moves as one so several objects keep their relative spacing, locked objects stay put and stay out of the bounding box, and an already-centred selection records no history entry.
- Arrow keys now move the selection towards the workplane axis closest to the direction the arrow points on screen, instead of along fixed world axes. The Front view and the default home view keep the mapping they always had, steps stay on an axis with no diagonals, and Ctrl/Cmd+arrow elevation changes and workplanes laid on a face are unaffected.
- The workplane now carries its name flat along its near edge, so which edge is the front is readable at a glance instead of having to be inferred from the symmetric axis lines. This also tells you which way an arrow-key nudge will move the selection, since those keys follow the plane's axes.
- Arrow keys now move the selection by the Snap Grid instead of a fixed millimetre, so a keyboard nudge lands on the same lattice a pointer drag snaps to. Shift keeps its coarser step, and the old 1mm/5mm steps stand when the grid is off. At the default 1.0 mm grid nothing changes.
- A snap grid or workspace setting chosen from a control now reaches the editor and the saved project immediately, instead of being swallowed until an unrelated change.
- Dimension marks now keep a minimum screen distance from the edge they measure, so a width or depth label is no longer hidden under a rotate handle when zoomed out. The rotate handle's hit area shrank from 52px to 40px around its 26px glyph, and dimension labels now sit on the same layer as the transform handles.
- Closing the window now quits SketchForge on Linux, where a system tray cannot be relied on. Windows and macOS keep hiding to the tray. A desktop that provides no tray no longer blocks startup, and the Linux launcher entry gained `GenericName`, `Keywords`, and `StartupWMClass`.
- Moved the project name field out of the tool ribbon and into the tab row above, so the Visibility, Combine, Modify, Arrange, and Manage groups stay reachable without the ribbon's horizontal scrollbar at narrower window widths.
- The Fillet toolbar marker and the shape inspector's length units are now keyed on property configuration rather than on visible English label text, so both keep working when the interface is translated.

## 1.0.9

- Corrected Top and Bottom camera views so they align exactly with the vertical axis in both perspective and orthographic projection.
- Added Ctrl/Cmd + right-button panning in Sketch mode while preserving middle-button panning.

## 1.0.8

- Duplicated objects now stay in the exact position of their source instead of receiving an automatic offset.
- Added geometry shortcuts: `R` rotates selected objects by 45 degrees and `Shift+R` rotates them by 22.5 degrees around the active workplane normal.
- Corrected rotation controls so objects turn in the direction indicated by the pointer on every rotation plane.
- Kept selection outlines, resize anchors, and height controls stable during close zoom while naturally hiding controls that leave the viewport.
- Kept object faces visible from inside the object and hid rotation controls while the camera is inside the selection.

## 1.0.7

- Raised the supported `project.json` size in `.skf` packages from 32 MiB to 64 MiB and compacted new project exports without removing editable data.
- Reused decoded derived-mesh data across restored history states to reduce memory pressure when opening large `.skf` projects.
- Prevented workspace-only changes from advancing the persisted shape revision and replacing newer live objects with an older snapshot.

## 1.0.6

- Fixed dense STL imports failing with `Invalid string length` while creating their initial undo-history fingerprint.
- Streamed large numeric mesh arrays into deterministic hashes instead of converting millions of coordinates to one oversized JSON string.

## 1.0.5

- Made the rotation handles larger and aligned their arrow glyphs with the model faces as the camera moves, including stable behavior on long objects.
- Positioned the lower rotation handle consistently at the model base and corrected its visual and drag directions.
- Added an optional **Select before moving** workspace setting so the first click selects an object without immediately dragging it.

## 1.0.4

- Fixed imported STL objects briefly appearing and then vanishing when a stale IndexedDB project read completed after the import.
- Prevented older persisted project data from overwriting newer live editor state during asynchronous project hydration.

## 0.1.0

- Initial open-source alpha.
- Browser-based 3D workspace with primitive shape editing.
- STL import and STL/OBJ export.
- Grouping and hole subtraction workflows.
- Local project dashboard with generated thumbnails.
