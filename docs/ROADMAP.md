## Desktop release installers

- [#345: Notify users when background checks find desktop updates](https://github.com/constructorfleet/SketchForge-3D/issues/345) — background update discovery now opens the existing update-available notice; regression-tested independently of a manual check.
- [#343: Document Windows installation and signing policy](https://github.com/constructorfleet/SketchForge-3D/issues/343) — Windows releases use the unsigned x64 NSIS installer until a signing certificate is configured; the README documents installation and SmartScreen, and the release and setup guides record the policy.
- [#545: Stop orphaning the desktop web server after a crash](https://github.com/constructorfleet/SketchForge-3D/issues/545) — implementation complete; awaiting review. The server child exits when its Electron parent disappears, and startup recognizes a SketchForge page already occupying the configured port. Covered by process-lifecycle and port-owner regression tests.
- [#342: Register the `.skf` file association and open files passed by the OS](https://github.com/constructorfleet/SketchForge-3D/issues/342) — implementation complete; awaiting review. The macOS app and Windows installer register `.skf` with the engine's media type; the Linux AppImage declares it in its desktop entry and documents the user-level MIME setup double-click needs. First-launch argv, `second-instance` argv and macOS `open-file` open the project through the dashboard's `.skf` import. Verified manually on macOS in dev mode; Windows and Linux are not yet verified by hand.
- [#344: Validate `SKETCHFORGE_DESKTOP_PORT` and explain a busy port](https://github.com/constructorfleet/SketchForge-3D/issues/344) — implementation complete; awaiting review. An invalid port falls back to 62158 instead of starting on `NaN`, with a console warning and a localized notice in the window; a port held by another program, or one the user may not listen on, stops startup with a localized error naming the port and the variable. The app no longer collides with its own web process when macOS reopens it mid-start or an update relaunches it. Covered by unit tests; both dialogs were checked by hand in an unsigned macOS arm64 `--dir` build. Windows and Linux are not yet verified by hand.
- [#543: Ship the CAD kernels in the packaged web bundle](https://github.com/constructorfleet/SketchForge-3D/issues/543) — implementation complete; awaiting review. `desktop:web:build` copies the Turbopack server externals (`occt-wasm`, `manifold-3d`) in place of their hashed links, and copies in `occt-wasm` under its plain name for the engine's STEP kernel loader. An electron-builder `afterPack` hook fails any package whose `Resources/web` has a dangling or linked external, or whose server imports a module that does not resolve inside it; it rejects the shipped 1.27.0 bundle. Verified on a local macOS arm64 `--dir` build copied outside the checkout: an OCCT fillet, a manifold thread and a STEP export succeed in the packaged app, and an ad-hoc `codesign --verify --deep --strict` passes. Windows and Linux packages are covered by the same hook but not verified by hand.
- [#547: Avoid duplicate desktop CAD kernels](https://github.com/constructorfleet/SketchForge-3D/issues/547) — implementation complete; awaiting review. The desktop build rewrites Turbopack's hashed external imports to package names so one OCCT and one Manifold package serve the standalone server, excludes those packages from `app.asar`, and verifies they stay absent there. The unused tracked `public/assets/occt` copy is removed; browser workers continue loading generated `/occt` files. A macOS arm64 `--dir` package contains one server copy of each package, one browser OCCT copy, and no kernel entries in `app.asar`; Windows and Linux use the same packaging checks but were not built locally.

## Client parity

- [#328: Derive the client operation parity matrix](https://github.com/constructorfleet/SketchForge-3D/issues/328) — completed in merged [PR #584](https://github.com/constructorfleet/SketchForge-3D/pull/584). `tests/unit/clientOperationParity.test.ts` invokes every mapped TypeScript and Python resource method with a stub transport, checks each outgoing method/path against the REST registry, and checks representative project id, page limit, and cursor query options. Composite bulk-delete helpers are inventoried separately and checked against their complete list/delete request sequence. It compares MCP's runtime `tools/list` inventory with explicit REST-backed and local/editor tool inventories, then invokes every REST-backed MCP handler against a fetch spy. TypeScript and Python cover all registered operations. MCP issues headless REST requests for 11 operations; the remaining 17 are explicit gaps, even where a local/editor tool offers similar behavior (for example, object CRUD, grouping and alignment). Project deletion and retained prism drafting have no MCP counterpart. **Caveat:** request option checks are representative; the parity test does not validate client payloads against each route schema.

Not covered: old cuts the migration cannot tell from those shapes (a face colour keyed by face ID, a pre-filleted operand, an edge resize mode), which still open at the origin.

- [#523: Build plain revolves as exact OCCT solids](https://github.com/constructorfleet/SketchForge-3D/issues/523) — `placedSolidForShape` builds a plain revolve, full turn or partial sweep about its recorded axis, from its profile, so properties, interference, wall thickness, distance measurements, cuts, groups, section drawings, SVG projections and server STEP export are exact when the profile is supported; a cut's display mesh is tessellated no coarser than the revolve's `sides`.
