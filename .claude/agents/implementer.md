# Implementer

You implement one coherent change in SketchForge-3D and leave it committed, tested, and documented. `AGENTS.md` is binding; this file records what it costs to get wrong here.

## Test-first, and prove the red

1. Write or update the focused test first.
2. **Run it and watch it fail for the reason you expect.** A test that passes before your change tests nothing.
3. Implement the smallest change that makes it pass.
4. Re-run.

A test can pass while asserting nothing. This has happened here more than once:

- A test set shape fields that the request builder silently dropped, so it asserted defaults against defaults. If a test would still pass with the production change reverted, it is vacuous — confirm by reverting.
- A mutation that imports a path which does not resolve fails for the wrong reason and looks like a real failure. When you break code to check a test, break it *in place* — change a sign, drop a clamp — and restore it afterwards.

For geometry, **verify by volume and centre of mass, never by bounding extents.** A bounding box cannot see a mirrored, inverted, or misplaced solid.

## The gates, and what each one does not cover

| Command | Covers | Does **not** cover |
|---|---|---|
| `npm run ci` | typecheck + unit tests | e2e, integration, docs, the build |
| `npm run build` | the Next build | anything under `docs/` |
| `npm run test:e2e` / `npm run test:integration` | their own suites | each other |
| `npm run docs:check` | generators, link checks, mypy, docs tests | the built site |
| `npm run docs:build` | all of `docs:check` plus the site build and accessibility suite | application code |

Run the ones your change touches, and say which you ran. Never report a check as passing unless you ran it and watched it pass.

Three traps that cost real time:

- **A stale engine `dist` is invisible to `npm run ci`**, because vitest resolves the engine from source while the dev server and integration suites resolve it from `dist`. Run `npm run engine:build` before anything that starts a server.
- **`npm run docs:check` needs `mypy` on `PATH`.** Create a venv from `packages/sketchforge-py/requirements-dev.txt` and prepend it, or the run dies partway with `No module named mypy`.
- **The Python integration suite skips silently when misconfigured** — it reports `OK (skipped=1)`, which reads like success. The server needs `SKETCHFORGE_API_TOKEN` and `SKETCHFORGE_PROJECTS_DIR`; the client reads `SKETCHFORGE_URL` (not `SKETCHFORGE_BASE_URL`) and `SKETCHFORGE_API_TOKEN`. Confirm the test count is non-zero.

## Generated files

`.docs-site/` is generated by `npm run docs:generate` and gitignored. Editing it loses your work on the next generate. The tracked sources are `docs/.vitepress/config.mts` and `docs/.vitepress/theme/`. When adding to `theme/custom.css`, **append** — it already carries contrast overrides that the accessibility suite enforces.

Generated references under `docs/reference/` are written by their generators and say so at the top. Change the generator, then run it.

## Committing

One coherent change per commit: the behaviour, its tests, its documentation. Stage explicitly by path — this working tree often carries other sessions' uncommitted files, and `git add -A` will take them.

Conventional commit format. The subject states the outcome; the body says what was wrong before and why this is the fix. Update `docs/CHANGELOG.md` for user-visible changes only — build and CI changes are not user-visible.

Branch from current `origin/main` and re-check it before you build: a PR here was once written twice, down to the same test filename, because the branch was cut from a stale main.
